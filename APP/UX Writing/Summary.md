FEATURE NAME
WARM & FAMILY-ORIENTATED UX WRITING
Category: UX / Content Design

============================================================
SUMMARY
============================================================

Purpose:
Defines ZYRA's unique tone of voice and UX writing
principles across the entire application.

Owns:
• UX writing philosophy
• UI wording standards
• Notifications
• Status messages
• Button labels
• Waiting states
• Milestone naming
• Human-centred communication guidelines

Referenced By:
• Every screen in the app
• Every notification
• Every Journey stage
• Every feature requiring user-facing text

------------------------------------------------------------
CORE PHILOSOPHY
------------------------------------------------------------

ZYRA should never sound like generic software.

Instead of describing what the system has done, it should
describe what the people have done.

Users should feel they are progressing through a meaningful
relationship rather than completing application tasks.

Every interaction should reinforce that ZYRA is
respectfully guiding two people — and where appropriate,
their families — towards marriage.

------------------------------------------------------------
GUIDING PRINCIPLES
------------------------------------------------------------

Every piece of wording should:
• Feel warm
• Feel respectful
• Feel family-orientated
• Feel calm and intentional
• Feel Islamic where appropriate, without being preachy
• Encourage rather than pressure
• Make progress feel meaningful
• Avoid gamification
• Avoid sounding technical or transactional

------------------------------------------------------------
PEOPLE BEFORE SOFTWARE
------------------------------------------------------------

The wording should describe human actions rather than
software events.

Avoid:
  Match Created / Stage Complete / Processing / Pending /
  Notification Sent / Request Received / Status Updated

Instead, describe what has happened between people:
  Salam Exchanged
  Ahmad has completed this step.
  You've both completed this step together.
  Your next step is ready.

------------------------------------------------------------
USE PERSONAL LANGUAGE
------------------------------------------------------------

Where appropriate, use people's names instead of generic
wording.

Examples:
  Waiting for Ahmad to send Salam.
  Waiting for Ahmad to complete this step.
  Ahmad has completed this stage.
  Ahmad's family has acknowledged your greeting.

Using names makes the experience feel personal rather than
system-driven.

------------------------------------------------------------
FAMILY PRESENCE
------------------------------------------------------------

The wording should naturally reinforce that families are
part of the journey where applicable.

Examples:
  Greet Ahmad's family.
  Ahmad's family has acknowledged your greeting.
  Your families have now been introduced.
  Both families can now view this stage.

The family element should feel natural, not forced.

------------------------------------------------------------
MUTUAL PROGRESS
------------------------------------------------------------

Progress should feel shared.

Avoid:
  You completed this stage.

Prefer:
  You've completed this step together.
  You're both ready for the next part of your journey.

Progress should always reinforce partnership.

------------------------------------------------------------
WAITING STATES
------------------------------------------------------------

Waiting should always explain why progress has paused.

Examples:
  Waiting for Ahmad to send Salam.
  Waiting for Ahmad to complete this step.
  Waiting for Ahmad's mother to acknowledge your greeting.
  Your journey will continue once everyone is ready.

Waiting should never feel frustrating or unclear.

------------------------------------------------------------
NOTIFICATIONS
------------------------------------------------------------

Notifications should feel personal and conversational.

Examples:
  Ahmad has completed this stage.
  Ahmad's family has acknowledged your greeting.
  Your next step is ready.
  You've unlocked the next stage together.

Notifications should never resemble system logs.

------------------------------------------------------------
RELATIONSHIP MILESTONES
------------------------------------------------------------

Milestones should read like meaningful moments in a
relationship, not application history.

Examples:
  ✓ Compatibility Reviewed
  ✓ Salam Exchanged
  ✓ Family Introduced
  ✓ Discovery Complete
  ✓ Values Shared
  ✓ Biography Revealed
  ✓ Conversation Opened
  ✓ Meeting Arranged
  ✓ Journey Continued

------------------------------------------------------------
SOFTWARE TERMINOLOGY TO AVOID
------------------------------------------------------------

Minimise or avoid:
  Complete / Processing / Pending / Status / Success /
  Request / Submit / Confirm / Workflow / Task / Queue /
  Synchronising

Where possible, replace with natural descriptions of
human events.

------------------------------------------------------------
ZYRA'S PERSONALITY
------------------------------------------------------------

ZYRA should feel like:
  • A calm host
  • A respectful guide
  • A welcoming presence
  • Patient and unhurried
  • Supportive throughout the journey

It should never feel like:
  • An administrator
  • A workflow engine
  • A checklist
  • A dating app
  • A game



------------------------------------------------------------
SWIPE-UP NAVIGATION RULE
------------------------------------------------------------

Transitional and milestone screens use swipe-up to
progress rather than a bottom button.

This applies to:
• Compatibility Reveal → next step
• Salam confirmed → next step
• Meet Their Guardians → next step
• Phase checkpoints → next phase
• Any screen that marks a shared milestone

Button-led navigation is for actions and choices
(Continue / Pause / End).
Swipe-up is for natural forward progression.

This keeps gesture language consistent throughout
the journey.

------------------------------------------------------------
YOU ↔ MARYAM, NOT SYSTEM → USER
------------------------------------------------------------

This is the single most important UX writing rule in ZYRA.

Every piece of language should feel like it exists between
two people — not between the user and the application.

WRONG (System → User):
  Salam Exchange
  Stage Complete
  Your Salam was sent.
  Continue to Guardian Gate.
  Begin with Salam.
  Send Salam.

RIGHT (You ↔ Maryam):
  Send your Salam to Maryam.
  Your Salam has been sent to Maryam.
  Maryam returned your Salam.
  You and Maryam exchanged Salam and began your
  journey together.
  Continue Journey.

RULE: Before writing any UI copy, ask:
  "Does this sentence mention Maryam (or the other person)?
   Does it describe what happened between two people,
   or what the system did?"

If the answer is "the system," rewrite it.

NEVER expose internal system names to users:
  Guardian Gate       → just continue naturally into it
  Stage 1         → describe what happens next
  Pre-Journey     → invisible to the user
  Profile Unlock  → name TBC, but not this

Users do not care what ZYRA calls things internally.
They care about what is happening between them and Maryam.

------------------------------------------------------------
STAGE / SYSTEM LABEL RULE
------------------------------------------------------------

Do not show clinical stage labels on screens where the
content already tells the user what is happening.

Wrong:
  SALAM EXCHANGE     ← clinical header
  Begin with Salam   ← generic title

Right:
  No label.
  Send your Salam to Maryam  ← personal, warm, clear

If a label is needed for orientation, it should be subtle,
secondary, and never the most prominent element on screen.

------------------------------------------------------------
APPROVAL TEST
------------------------------------------------------------

Before approving any UX wording, verify:
• Does it sound like people rather than software?
• Does it mention people by name where appropriate?
• Does it make the journey feel intentional?
• Does it reinforce respect and modesty?
• Would it still feel meaningful without the surrounding UI?
• Does it sound uniquely like ZYRA rather than a generic
  dating application?

------------------------------------------------------------
OVERALL GOAL
------------------------------------------------------------

If the interface were removed and only the text remained,
users should still recognise ZYRA through its unique
tone of voice.

Every interaction should make users feel:
• Welcomed
• Respected
• Guided
• Unhurried
• Supported

The language itself should communicate that ZYRA is
thoughtfully guiding two people — and, where appropriate,
their families — through a respectful journey towards
marriage.
