The implementation deliberately separates candidate capture from baseline authority. It can measure and fail; it cannot redesign, rewrite product language, approve a screenshot, close an OA or enable a recurring job.

## 2 · Architecture and data flow

1. `zyra_visual_gate.py` fingerprints UI-affecting Dart, visual-test, asset, configuration, matrix and approved-manifest inputs.
2. An unchanged fingerprint exits immediately at $0.00.
3. A changed/forced run regenerates inventories and L1 findings, then runs formatter check, analyzer, `zyra_check`, visual tests, optional candidate capture and optional full suite.
4. `zyra_visual_regression_test.dart` applies matrix-controlled role/plan/device/text/stress fixtures to live shared widgets.
5. Normal mode compares only explicitly approved manifest rows. Capture mode writes only to `test/visual/candidates/`.
6. Stable fingerprints update `visual_state.json`; each run writes a permanent Markdown report and candidate manifest with hashes.
7. AIOS `/ui-consistency` reads those files and presents history, findings, candidate comparisons, source and governance references without mutation controls.
