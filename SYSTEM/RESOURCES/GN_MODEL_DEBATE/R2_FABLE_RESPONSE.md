## FINAL AGREED MODEL (goes to the Founder for ratification as decision D14)

**Purpose.** The Guardian Network is a Main-Wali ↔ Main-Wali connection space. Seekers receive nothing until Rung 4, and then both at the same moment. Seeker-side progress lives on the Guardian Dashboard.

**The ladder.**
- **Rung 0 — Recommendation.** Algorithm-served, one family at a time, for one selected Seeker context; no browse-ahead, no search; privacy-minimal card (initial · age · region · band · relationship label · verified badge · photo only at Seeker's card-level permission). Actions: View · Set aside · Request connection.
- **Rung 1 — Request connection.** Main Wali sends (cap: 3 outstanding per Seeker context, all plans); receiver's Main Wali sees it under Connections → Incoming with the reciprocal privacy-matched card; sender sees Sent → "Awaiting their Wali". Receiver may accept ("Connect with this family") or clear internally ("Not for us"). A pending reverse request auto-merges as acceptance (and merges into Discover, F2).
- **Rung 2 — Connected.** Reciprocal, simultaneous, consent-limited unlock: verified Main-Wali profile, relationship, region, verification status, the Seeker's ordinary Browse-level profile, photo per the Seeker's photo permission, structured exchange (no free text in v1). Never: contact details, exact location, private answers, numeric scores, other-network membership, message history, safety history, Journey history.
- **Rung 3 — Proceed to the Seekers.** Each Wali independently confirms; either may withdraw silently before both have confirmed (state updates honestly as "No longer active").
- **Rung 4 — Simultaneous introduction.** Both Seekers receive it at the same moment and decide independently under all ordinary ZYRA rules.

**Decline discipline.** Default decline is silence: 14-day quiet expiry; sender sees only "No longer active" — one external state for every internal cause (decline, expiry, withdrawal, eligibility change, Guardian change, safety). No reasons, no decline notifications, nothing to either Seeker. Explicit "Not for us" → 6-month pair cooldown, both directions, Wali-switch-proof. Post-expiry re-request: 90 days; second expiry → closure with the 6-month pair cooldown (F1).

**Eligibility.** `can_introduce()` and all gates re-checked at serve, send, accept, proceed and reveal; any failure closes the process neutrally.

**Consent.** Separate Seeker controls: participate in Guardian Network · photo level (card / after-connect / never — default after-connect) · pause recommendations. Prospective only; can't-unsee recorded honestly.

**Calm delivery.** Badge + at most one daily digest; no per-request push; lock-screen copy carries no Seeker identifiers.

**Supersession.** Within the Guardian Network, this ladder supersedes the earlier initiator-led "Family Introduction Request" draft chain and the ambiguous use of "Suggest" for cross-family action ("Suggest to Seeker" remains what it always was: a private advisory nudge to one's OWN Seeker, unchanged). The truncated draft contract's rules 22+ will be completed against THIS model.
